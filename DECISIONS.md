# Implementation decisions

## 2026-10-09 — Task 2 dataset adapter and redistribution

- Implemented an independent, standard-library CSV/ZIP streaming adapter for the Deep Sorting dataset. It prefers `Battery_ID` and `Protocol_ID` in each raw row and falls back to the source filename only when the battery ID column is absent.
- The adapter uses `Cycle_Index`, `Step_Index`, and `Discharge_Capacity(Ah)` from the authors' version 1.0.0 public extraction release to confirm the CSV schema. It extracts capacity-bearing diagnostic cycles using `Cycle_Index % 5 == 1`, the published one-in-five cycle selection, and stores the maximum valid discharge-capacity value within the cycle. Resistance and temperature are per-cycle means of valid samples. Full waveforms are discarded.
- The full second-life schema scan exposed `Aux_Temperature_1(C)` as the temperature column. The adapter maps this source header into canonical `temperature_c`; `Aux_Temperature_1(C)` and common unit variants are covered by alias tests. The first scan report predated this mapping and therefore showed temperature as unresolved.
- Numeric parsing is tolerant of common null tokens, non-finite values, decimal-comma values, and whitespace. Zero capacity and resistance entries are treated as raw reset/unmeasured sentinels; accepted capacity values are positive and at most twice the configured nominal capacity, resistance values are positive and at most 10 ohm, and temperature is between -50 C and 120 C inclusive. Rejected values are counted and reported. These broad envelopes are data-quality guards, not battery safety limits.
- The Zenodo data record's Rights/License field is blank in the public record as checked October 9, 2026. Redistribution permission for cell-level or derived cell records is therefore unresolved. The repository contains no real processed observations. Local preprocessing marks results `derived-real`, writes source checksums/provenance, and warns against redistribution. The only checked-in battery-shaped records are hand-authored synthetic fixtures for tests and UI development.
- SHA-256 values are calculated while each raw CSV is read; for ZIP inputs, the digest is over each uncompressed CSV member. The compact JSON serialization is stable by schema/key order and rejects NaN/Infinity.
- On October 9, 2026, the full archive inspection confirmed 86 files and 57,627,675 rows. A complete extraction pass read all 86 files, but the sandbox shell rejected creating `data/processed` with `Errno 30` (read-only filesystem), so it did not save its in-memory results. Run `src/scripts/preprocess_primary.py` in a writable checkout to produce and review the final trajectory and provenance summaries.
- The workspace's `.git/` directory is empty and read-only, so the Task 2 local commit cannot be created in this environment. No remote or replacement repository metadata has been created.

## 2026-10-09 — Task 1 scaffold and environment spike

- Use the Python `backend.run(circuit, shots=...)` interface and `job.result().get_counts(circuit)` for the local smoke path. The helper accepts an injected backend object so later Qollab integration can supply its backend without embedding credentials or provider setup in the algorithm code.
- Use Qiskit's built-in `BasicSimulator` for the local/free simulator check. It ships with the core Qiskit package and avoids adding Aer until a later task establishes a need for it.
- `BasicSimulator.run(circuit, shots=N)` returns a job object; `job.result().get_counts(circuit)` returns counts synchronously for this local simulator. Passing a backend object into `run_smoke_test(backend=...)` was verified with `BasicSimulator`; the helper does not configure credentials or a provider.
- Qiskit count strings follow the classical-register display convention: the leftmost character is the highest-index classical bit and `c[0]` is rightmost. The verified X-on-q0 circuit returned `{"01": 32}`; the helper decodes that as `[1, 0]` in q0/q1 order. This matches the [official Qiskit Result API](https://qiskit.qotlabs.org/docs/api/qiskit/qiskit.result.Result).
- The workspace interpreter is CPython 3.14.4. The initial environment had no `pip`, no `venv` support, and no Qiskit/NumPy/SciPy. Network access from the ordinary sandbox was unavailable. With the user's authorization to download and set up the environment, `uv 0.13.0` was downloaded to `/tmp` and Qiskit 2.5.2 was installed in `/tmp/repackq-env`; NumPy 2.5.3 and SciPy 1.18.1 are present there. Qiskit installed successfully on Python 3.14.4. A `Statevector` calculation and SciPy `minimize` call both ran successfully.
- Package installation into a project-local `.venv` failed because the mounted workspace denied wheel writes under `.venv`; the temporary environment in `/tmp` is used for local validation. The repository documents the standard setup for a normal developer machine.
- Qollab-specific facts remain unverified: Python runtime version/package set; free backend object type; whether `.run()` is synchronous or returns an asynchronous job; count retrieval API and bit ordering; JS-to-Python invocation; Statevector and SciPy support in that runtime; local JSON asset support; and limits on concurrent/multiple remote simulator jobs. Qollab's cited documentation was not accessible from the available network tool, and no Qollab runtime or connector is installed in this workspace. No platform API is guessed. The bridge is isolated behind an adapter contract until the runtime probe is run inside Qollab and its output is reviewed.
- No Qollab or remote backend job was run in this workspace. The local simulator path is verified separately; a Qollab UI-to-Python round trip remains pending the user's Qollab probe output.

## 2026-10-10 — Task 3 trajectory modeling and retrospective pools

- Added immutable canonical `CellSnapshot`, `FutureTruth`, `MissionProfile`, and `CandidatePool` records. `CellTrajectory.history_through(t0)` and `future_after(t0)` create disjoint tuples; the estimator and snapshot builder reject any history tuple containing a cycle after `t0`.
- The weighted linear capacity model uses the latest eight valid capacity diagnostics, requires four, and applies `linspace(0.5, 1.0)` weights. It uses a deterministic median pairwise slope fallback, clamps positive slope to zero, clamps predictions to `[0, current capacity]`, and caps the residual-propagated uncertainty proxy at 25% of nominal capacity.
- A valid capacity diagnostic at exactly `t0` is required. This keeps the stated `C_now + slope * H` forecast anchored to the same cycle for every candidate; cells without a current reading are filtered from that pool.
- Future truth is looked up only from the future-side tuple using `max(5, round(0.05 * H))` cycle tolerance. Prediction evaluation reports MAE, RMSE, safe-denominator median absolute percentage error, and future-truth coverage over cell-by-decision-cycle forecasts; overlapping cutoffs are labeled.
- `pv_tou` implements the locked 200-cycle mission weights. `frequency_response` is explicitly marked experimental and reuses the same model/weights as a placeholder, with no mission-specific degradation claim.
- Candidate pools use seeded random sampling, optional protocol round-robin stratification, current SOH minimum/range checks, and stable SHA-256 IDs. Eligibility may require a valid future measurement, but no future value participates in snapshot construction, heterogeneity checks, sampling, or default-pool selection.
- The demo builder refuses synthetic data. Its default pool is selected from at least three fixed-seed pools as the one closest to the median predicted pack divergence, without inspecting held-out outcomes. Generated real-data pool/evaluation JSON is local and ignored by Git because dataset redistribution terms remain unresolved.
- Added focused estimator, future tolerance, physical metric, pool reproducibility, protocol-stratification, evaluation-summary, and hard no-leakage tests. The full suite passed: 29 tests.
- The available 1.7 GB second-life archive was processed locally into `/tmp/repackq-task3/processed/`; 86 trajectories were extracted. Held-out evaluation used 7,910 predictable cell/cutoff points, with 4,642 valid future matches (58.69% coverage), MAE 0.11465 Ah, RMSE 0.16498 Ah, and median absolute percentage error 5.5516%. Cutoffs within cells overlap; these figures evaluate this simple predictor on this retrospective dataset only.
- Three seeded demo pools (seeds 11, 29, 47), each with 8 candidates and 8 future truth records, were generated at decision cycle 16. The default is `pool-df9a0e39aae4c119`, selected as nearest the median predicted pack divergence. No held-out outcome was used to select it. Pool and aggregate outputs remain under `/tmp` because the workspace rejects writes to `data/processed`.
- Identifier audit: the Zenodo record states that source filenames use the original experiment labels while the embedded `Battery_ID` uses separate manuscript identifiers. Thus, unavailable original labels 61/62 are the absent files `61.csv`/`62.csv`; embedded `Battery_ID` values 61/62 in files 37/38 are present cells. The raw archive contains filenames 1–60 and 63–88, and the preprocessing run produced 86 trajectories. See [the dataset record's file-identification note](https://zenodo.org/records/14859405).
- No Qollab runtime or backend command was run. The local `.git/` directory is empty, so the Task 3 commit cannot be created in this workspace.

## 2026-10-10 — Task 5 Qiskit QAOA engine and local backend

- Added a Qiskit compatibility layer for `SparsePauliOp`, the p-layer diagonal cost evolution/X-mixer ansatz, named gamma/beta binding, Statevector expectations, and backend transpilation. Ising labels map project qubit 0 to the rightmost Pauli character. Identity terms remain in expected-energy calculations and are omitted only from circuit evolution as a global phase.
- Added a single candidate-index/Qiskit-count codec and a deterministic four-qubit q0/q2 decoding sanity helper. QAOA decoding uses classical-bit width, so transpilation that adds physical qubits does not change the candidate mapping.
- Added local statevector parameter optimization: deterministic COBYLA when SciPy is available, plus a dependency-light p=1 12×8 gamma/beta search with three shrinking local refinements. Optimizer calls cannot access a backend. The final sampling stage makes one `backend.run(...)` call.
- QAOA results include raw and normalized counts, feasible samples ordered by physical objective, best feasible and modal states, feasibility and exact-optimum mass, sampled optimality gap, calibrated penalty, circuit and transpiled depth/size, backend label, timing breakdown, and the common physical pack result. An infeasible sample set remains explicitly infeasible with no repaired recommendation.
- Added `run_qaoa_demo.py` for running a saved real/derived-real pool export on Qiskit `BasicSimulator`; it refuses synthetic-fixture inputs. The engine accepts injected Qiskit backends but does not guess Qollab provider APIs.
- Validation used Qiskit 2.5.2 from `/tmp/repackq-env`. Eight focused QAOA tests and the full 46-test suite passed, including exhaustive operator-vs-Ising energy checks, p=1/p=2 parameter binding, grid fallback, bit-order sanity, end-to-end toy QUBO, and no-feasible-sample handling. The required N=8/K=4 local run also completed on the existing derived-real Task 3 export with 1024 shots and one BasicSimulator job; generated cell-level inputs/results were not copied into the repository because dataset redistribution terms are unresolved.
- Qollab-specific transpilation/backend execution remains unverified because the runtime probe has not been run inside Qollab. This is not a blocker for the local Qiskit Task 5 engine; it remains a platform-integration dependency before Qollab deployment.
- The workspace `.git/` directory is empty and read-only; a local Task 5 commit cannot be created here.

## 2026-10-10 — Task 6 reproducible benchmark and aggregate exports

- Added `configs/task6_benchmark.json` with the 20 predeclared SPEC seeds, N=8/K=4, decision cycle 16, H=200, 3,000 annealing steps, p=1 QAOA, 1,024 shots, and deterministic simulator seeds. `src/scripts/run_benchmarks.py` accepts canonical trajectory JSON or a matching pool export, generates/reloads pools, and writes a fsynced single-record-per-line checkpoint so interrupted runs can resume without losing completed trials.
- Each valid trial compares SOH sort under the current-only score, greedy, annealing, exact, and local QAOA. Exact current-only and exact trajectory-aware selections are paired on the same pool for the OPD ablation. QAOA parameter search uses local Statevector; the benchmark's default sampling uses local Qiskit BasicSimulator. An explicitly selected injected backend can run once for one configured seed. No Qollab or remote backend was invoked for Task 6.
- The fixed 20-seed real-data run completed at cycle 16. Greedy, annealing, and exact trajectory-aware methods matched the exact objective on all trials. QAOA returned a feasible sample on 20/20 trials; the exact optimum was sampled on 17/20 (85%), with mean best-sampled objective gap 0.08948 and mean feasible shot mass 0.29307. Mean local QAOA total time was about 1.5 seconds, versus about 4.34 ms for exact enumeration and 69.28 ms for annealing; no speedup claim is made.

These are descriptive draws from one inventory and pools may overlap; they are not independent battery populations or a significance test.
- Predictor validation from the matching Task 3 export reports 4,642 held-out forecasts, MAE 0.11465 Ah, RMSE 0.16498 Ah, median absolute percentage error 5.55159%, and future-truth coverage 58.69%. The forecast cutoffs within each cell overlap.

The web replay assets contain only aggregate pack metrics for three trials selected by predeclared seed order, with no cell IDs, snapshots, or pack membership. The dataset record still has no stated redistribution license; `redistribution_license_verified` is false and the full trajectory and trial inputs are not checked in.
